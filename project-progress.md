# Прогресс проекта DubParty

## Текущий статус

- [x] Этап 1: GUI, лобби и базовая проверка подключения подготовлены.
- [x] Этап 2: проекты фильмов и редактор видеосцен.

## Этап 1

Реализованы React/TypeScript UI, Tauri 2 оболочка, FastAPI управляющий API и WebSocket сервер лобби. Есть выбор IPv4 интерфейса, запуск только на выбранном адресе, чат, история до 300 событий, список участников, системные сообщения, серверная проверка ника/сообщений, host token, возобновление сессии по серверному токену и heartbeat очистка соединений. Управляющий API привязан к loopback. Инструкции ручной проверки находятся в `docs/testing.md`.

Проверено: `npm run build` (TypeScript и Vite 7 build), `python -m compileall -q backend\app`, `npm audit` (0 уязвимостей). Интеграционный сценарий на текущем компьютере использовал интерфейс Radmin VPN: создание комнаты, три клиента, обмен сообщениями, выдача истории позднему участнику, конфликт никнейма, выход, переподключение с сохранением UUID, остановка и создание следующей комнаты. Проверены некорректный IP, пустой никнейм и занятый порт; конфликт порта не завершил управляющий backend.

Добавлен и проверен `run-dubparty.cmd`: запускает backend и frontend одним окном, открывает URL для ручного перехода и останавливает созданные процессы по `exit`. После выхода оба порта освобождаются, временный файл launcher удаляется.

Launcher автоматически скачивает portable Node.js/Python и устанавливает зависимости в `.runtime`, поэтому пользователям не требуется вручную устанавливать Node.js/npm или Python. Проверен запуск portable runtime, готовность backend/Vite, команда `status` и остановка по `exit`; после выхода порты 8765/1420 свободны. На первом запуске понадобилось сетевое разрешение, так как sandbox блокировал доступ к источникам runtime.

## Этап 2

Общий чат содержит действие создания проект-комнаты с названием и видеофайлом. В каждой проект-комнате доступны вкладки просмотра, редактора и отдельного чата; озвучка пока отмечена как будущий раздел. Список комнат рассылается участникам, а сервер хранит отдельную историю общего чата и каждой проект-комнаты в памяти. Новый участник получает список комнат; хост восстанавливает его после перезапуска сервера из локальных JSON-проектов. Гости могут открывать комнаты и общаться, но видео пока остается у хоста.

Проекты и видеофайлы хранятся отдельно от метаданных. `run-dubparty.cmd` использует `.dubparty-data\projects`; переменная `DUBPARTY_DATA_DIR` задает другой каталог. Backend возвращает понятное сообщение, если каталог недоступен для записи. Импорт, чтение, сохранение и HTTP Range остаются доступными через loopback API.

Проверено: `npm run build`; `.runtime\python\python.exe -m compileall -q backend\app`; HTTP интеграция импорта проекта с названием, сохранения/чтения, проверки неправильных таймкодов и HTTP Range; WebSocket интеграция списка проект-комнат, изоляции истории между общим чатом и проектной комнатой, восстановления истории и выдачи списка новому участнику. UI и воспроизведение настоящего видео вручную не проверены: браузерная политика среды заблокировала автоматическое открытие локального URL, а тестовый фильм отсутствует.

Воспроизведение использует одну нижнюю панель управления: воспроизведение/пауза, позиция, громкость и полный экран. Во вкладке просмотра добавлено переключение «Оригинал»/«Переозвученная версия»; пока оба режима намеренно используют исходный видеофайл. В редакторе убраны нативные контролы video, добавлен синхронный playhead, секундные деления таймлайна и прокрутка за playhead при выходе из видимой области. Launcher сравнивает SHA-256 `package-lock.json` и `backend\requirements.txt`, устанавливая зависимости при их изменении или отсутствии.

Повторно проверено: `npm run build`, Python `compileall`, разбор `run-dubparty.ps1`, контрольные суммы lock-файлов, HTTP readiness backend/frontend. Визуальные действия с реальным видео требуют ручной проверки через локальное приложение.

Дополнительно добавлены drag-to-pan для пустой области таймлайна и scrubbing playhead мышью. Позиция плеера/таймлайна округляется до 500 мс и показывает половины секунд в таймкоде; стрелки влево/вправо шагают на 1 секунду, пробел управляет воспроизведением с исключением полей ввода, кнопок и редактируемого текста. Проверено повторной сборкой TypeScript/Vite, Python compileall, синтаксисом launcher и доступностью backend/frontend. Жесты мышью и клавиши нужно подтвердить вручную в приложении.

Исправлена потеря шорткатов после фокуса на блоке реплики или кнопке добавления: клавиатурный обработчик работает в capture-фазе и отменяет нативную прокрутку/активацию кнопки для пробела и стрелок. Исключены только поля ввода, select и редактируемый текст.

Добавлено масштабирование колесом при наведении на таймлайн с удержанием временной точки под курсором; существующий range-контрол остаётся доступным. Требует ручной проверки положения при прокрутке и обоих способов масштабирования в UI.

Колесо над редактором теперь предотвращает прокрутку родительской страницы; горизонтальные wheel-жесты прокручивают сам таймлайн. Добавлены Delete для удаления выбранной реплики и стрелки вверх/вниз для перемещения по дорожкам. Дорожка сохранена в метаданных реплики, конфликты временных интервалов раскладываются на свободные дорожки, а перемещение пропускает занятые интервалы.

Подробности ручной проверки проекта описаны в `docs/testing.md`, хранение и границы доступа — в `docs/architecture.md` и `docs/development.md`.

При сообщении пользователя `svgNetworkError when attempting to fetch resource` ошибка не воспроизвелась: локальные `/api/health`, `/api/projects` и frontend отвечают HTTP 200, CORS подтверждён для Vite и Tauri origin. Текст отсутствует в исходниках; обработку ошибок видеоплеера уточнил по кодам `MediaError`, а сообщения о недоступном backend дополнены командой `status`. Если ошибка повторится, нужен точный шаг, на котором она появляется, и снимок экрана: в текущей среде браузерный интерфейс вручную открыть не удалось.

## Известные ограничения

- Связь между двумя отдельными компьютерами через Hamachi/Radmin не проверена; выполнен локальный тест привязки к интерфейсу Radmin VPN.
- Desktop окно Tauri не собрано и не открыто: в среде отсутствуют `cargo` и `rustc`. Dev-сервер Vite запускается отдельно, но доступная Windows browser automation остановила открытие приложения из-за ограничений обработки URL.
- Установочная сборка и доставка Python runtime пока не настроены.
- WebSocket трафик не шифруется, а подключение не требует аккаунта или подтверждения участника; токены нужны только для назначения хоста и возобновления сессии.

## Этап 3

Launcher ищет системные FFmpeg/FFprobe и использует их, если доступны; иначе скачивает Windows essentials build в `.runtime\ffmpeg`. Локальный backend предоставляет проверку версии, фоновую подготовку аудио с прогрессом и отменой. Для каждого проекта первая звуковая дорожка исходного видео конвертируется в `audio/prepared.wav` PCM s16le, 48 кГц, stereo. Ссылка хранится в `project.json`, аудиоданные отдельно. В редактор добавлены статусы, повторная обработка, отмена и загрузка результата. Это обычное извлечение/преобразование FFmpeg; AI-разделение стемов не реализовывалось.

Проверено: `npm run build`, Python compileall, PowerShell parse. На реальном FFmpeg 9.0.2 проверен полный HTTP-сценарий с тестовым H.264/AAC видео: readiness FFmpeg, запуск, прогресс/завершение, скачивание WAV, метаданные и `ffprobe` подтвердил `pcm_s16le`, 48000 Гц, 2 канала. Отдельно проверены отмена 120-секундной обработки и отказ для видео без аудиодорожки. Автоматизация GUI и реальный пользовательский фильм требуют ручной проверки.

## Этап 4

Добавлена локальная интеграция с Demucs и PyTorch. В редакторе хоста показываются состояние зависимостей, версия модели, наличие CUDA и кэш весов. Demucs устанавливается отдельной кнопкой в portable Python runtime, поэтому тяжёлая ML-зависимость не скачивается при обычном запуске лобби. После подготовки WAV хост может выбрать Auto, CPU или CUDA, запустить разделение и отменить фоновый процесс.

Используется модель `htdemucs` в режиме `--two-stems=vocals`. После успешной обработки в проект публикуются две WAV-дорожки: `vocals.wav` и `accompaniment.wav`; временная директория удаляется при ошибке или отмене. API отдаёт статусы и ссылки для скачивания. Это разделение вокала/голоса и остального микса, а не выделение отдельных персонажей.

Проверено: TypeScript/Vite build, Python compileall, маршруты `/api/stems/status` и `/api/stems/install/status` во временном backend, отсутствие ложной готовности при неустановленных Demucs/PyTorch. Полный прогон модели не выполнен: текущий runtime не содержит ML-зависимости и модельные веса.

## Исправление запуска на чистом Windows

По сообщению об ошибке `esbuild` выяснилось, что npm запускает пакетный install-скрипт `node install.js`, но portable Node.js не был доступен дочерним процессам через `PATH`. Launcher теперь проверяет наличие `node.exe` и добавляет каталог `.runtime\node` в `PATH` до вызова npm. Обновлена инструкция запуска. Проверка npm и дочерней команды `node` с очищенным системным PATH выполнена локально.
